# Hints: developer guide

The technical side of Hints. The friendly overview for family is the [README](../README.md).

Wish lists for your circle (family, friends, whoever you gift with) at **hints.alexisdavidson.org** (the old **wishlist.alexisdavidson.org** redirects there, invite links included; sign-ins are per domain, so people sign in once on the new one). Mark what you're getting someone (hidden from the list owner) and keep private gift notes per person. Installable on phones as a PWA.

One Cloudflare Worker with a D1 database. No build step.

## Layout

```
wrangler.jsonc        Cloudflare config: Worker, custom domains, D1 binding
src/worker.js         Router: /api/* to wishlist.js, /join/CODE invite pages (with link previews), everything else from public/
src/wishlist.js       API and privacy rules (D1)
src/gemini.js         Gemini call used by photo search (with the app-wide daily cap)
src/limits.js         Abuse limits: rate limits, quotas and caps (see Abuse limits)
src/push.js           Web Push: VAPID signing and payload encryption (notifications)
src/stores.js         Stores photo search may link to, plus blocked marketplaces
migrations/           D1 schema (wrangler d1 migrations)
public/index.html     The app (single page)
public/sw.js          Service worker (network first, offline fallback)
public/manifest.webmanifest, icons/, fonts/ (Figtree, Bricolage Grotesque, OFL)
public/theme.js       Applies the saved light/dark choice (picked in Settings)
public/xlsx.js        Builds the budget Excel export (Settings) in the browser
public/giftcards.js   Gift card brands (name, color, emoji, group). Loaded by the app and imported by src/wishlist.js
public/qr.js          Makes the invite QR code (SVG), loaded only when someone taps "Show QR code"
public/og-invite.png  Link preview image for invite links
```

## Deploy

**First time**
1. `npm install`
2. `npx wrangler login`
3. `npx wrangler secret put GEMINI_API_KEY` (photo search; key from https://aistudio.google.com/apikey)
4. `npm run migrate` (applies any migrations not yet applied to the `wishlist` D1 database)
5. `npm run deploy`. The custom domains in `wrangler.jsonc` attach themselves.

**After that:** connect the repo in Cloudflare (Workers > wishlist > Settings > Build, root directory `/`) to deploy on every push to `main`, or run `npm run migrate && npm run deploy` by hand.
- Deploy command: `npm run migrate && npm run deploy`, so new migrations are applied before the new code goes live and merging is all it takes.
- Build token: needs Account > D1 > Write (Edit) for the migrate step. The token Workers Builds makes by default doesn't have it.

**Local:** copy `.dev.vars.example` to `.dev.vars`, then `npx wrangler d1 migrations apply wishlist --local` and `npm run dev`.

**Checks:** GitHub Actions runs `npm run check` (a `wrangler deploy --dry-run`) on every push and PR.

## How it works

- **Sign-in** is the honor system: a circle's invite code, then pick your name (or add yourself). A 4-digit PIN is optional and protects your private notes. Each device keeps a token in localStorage. A forgotten PIN can be cleared by anyone in that person's household or by the admin of a circle they're in (Clear PIN in Manage on the Circles tab, or Settings > Household); the PIN screen's "Forgot your PIN?" says who to ask. The person sees "Your PIN was cleared" with who did it until they set a new one or dismiss it (`members.pin_cleared_by`, migration 0024).
- **Privacy rules** live in `src/wishlist.js`: the list owner never gets purchased marks, private ideas only go to their author, and you only see lists of people in a family you share.
- **Occasions:** purchased marks and budgets belong to an occasion: Christmas for everyone, plus each person's birthday (from their profile). The `season` columns hold the occasion's date as YYYYMMDD and count through that day in New York, then reset; wishes carry over (migration 0011). "I'll get this" asks which one it's for (soonest by default) when the person has a birthday, so a Christmas gift bought before a November birthday stays marked. Changing your birthday moves what family planned for the old date to the new one. Birthdays are month and day only: Hints never asks for a birth year or shows anyone's age (migration 0032 dropped `members.birth_year`). The Circles tab shows "Birthday in 12 days" in the month before. The "When's your birthday?" card on My list opens a small month and day sheet and saves it right there. Removing an item someone already bought keeps it for the buyer, flagged "removed".
- **Invite links:** `/join/ABC234?from=memberId`. The Worker serves the app page with the title and Open Graph tags swapped ("Join The Davidsons on Hints", "Alexis invited you...") so pasted links show a nice preview card. The page opens on an invite screen: an envelope opens, the family's avatars pop in, and one Join button leads to "Are you new here?" (new people first, returning people tap their name). A bad code gets a friendly "That invite didn't work" screen with a code box. Old `/?code=ABC234` links still work. Opening an invite while signed in asks "Join The Davidsons?" in a sheet (or does nothing if you're already in it).
- **Invite card:** the Circles tab while it's just you (and the Invite buttons on the Circles tab, in Settings and per family) shows a ticket with the code, Copy invite (warm message, link, and code), Send (the phone's share sheet), and Show QR code for inviting someone in person.
- **Welcome tour:** after joining, a full-screen set of swipeable cards, each with a small animation: welcome, adding wishes, surprises stay hidden, private notes and budgets, an optional PIN, adding to the home screen, and (for someone who started a family) inviting the family. Shown once per person (`members.onboarded_at`, migration 0007; people from before it count as done). Settings has "Replay the welcome tour".
- **Install nudge:** a "Get the Hints app" card at the top of My list, only where installing is possible and never during the welcome tour. Chrome, Edge and Samsung Internet get one-tap Install (their own `beforeinstallprompt`, which stops firing once it's installed). Safari on iPhone and iPad gets "Show me how": numbered taps with the real Share and Add to Home Screen icons, including the ••• menu on newer iPhones, plus a reminder that the home screen app needs one sign-in (it keeps its own storage), with the family code. Chrome, Edge and Firefox on iOS get their own steps. In-app browsers (Instagram, Facebook, Gmail, Google app, Android webviews) are told to open the page in Safari or Chrome first, with a Copy link button. "Not now" snoozes it for 7 days, then 30, then stops. "I've added it" or a real install turns it off for good. All of this is per browser in localStorage (`wishlist-install`). Settings > App always has the button.
- **Yearly refresh:** in November, My list shows "Your list hasn't changed since last year" when no published wish was added or edited since January 1, with Drop a hint and Looks good (hides it until next November on every device, `members.stale_ok_year`, migration 0027, which also skips that year's reminder notification).
- **Getting started:** an empty My list suggests ideas (a book, something cozy, ...) and asks for 3 wishes, with a progress bar until the third, which gets confetti.
- **Adding:** the center + (and every other Add button) opens one sheet that starts with "Who's it for?": a Me / Someone else switch (Me is the default). Someone else shows who's picked as one chip; tap it to change, from a list with search once there are more than 8 people. Switching to Someone else picks the last person you chose (remembered until the app reloads), or opens the list if there isn't one. Me gives the wish form (saves to Maybe); anyone else gives the gift-idea form for them. Switching keeps the name, link, price, notes and photo. Someone's page and their Budget card open it with them picked; the Budget tab's Gift idea button starts with nobody picked. Editing and Add a purchase don't show the switch. An idea saved for someone whose page you're not on gets a View shortcut in the toast. A new wish has two buttons: **Add to Maybe** (private) and **Add to wish list** (saved and published in one step). Pressing Enter picks Add to Maybe.
- **Link first:** new wishes, gift ideas and purchases open with the link box on top and focused, with a Paste button that reads the clipboard and fills in the rest (it becomes Fill once there's a link); "Or type what it is" and the photo option come below. Editing keeps the old layout. Pasting a link anywhere in the app (outside a text box) opens the add sheet with it, and a link pasted into the name box moves to the link box. On Android with the app installed, Hints appears in the Share menu (`share_target` in `public/manifest.webmanifest`, read from `?share_title/share_text/share_url`); iPhones don't allow that for web apps, so there's an **Add to Hints** Shortcut instead: Settings > Add from the Share button makes a personal add key (`members.add_key_hash`, migration 0038, only the hash is kept), and the Shortcut sends the shared text with it to `POST /api/quickadd`, which fills it in like Fill and saves it to Maybe, answering with one plain sentence the Shortcut shows as a notification. Set up and sharing the Shortcut: `docs/plans/native-app.md`. Pages titled "Security Check" (TikTok) count as bot pages, so the name comes from the shared text instead.
- **Wish cards:** size, color (with a swatch when the name is a color we can draw), category and store show as small chips under the name. The brand sits above the name in small caps: the saved brand, or the store's name when the title starts with it ("Zara Puffer" from zara.com), and isn't repeated in the name.
- **My list views:** compact cards (photo, name, one line of chips with price first, star on the right). A toolbar shows once a side has 2+ wishes: search (5+), layout (List, Gallery, Shelves grouped by category), sort (Newest, Top picks first, price, A to Z, By store, remembered per device in `wishlist-mine-view`), and filter chips (Top picks, categories, price ranges) built from what's on that side. Filters repaint only the cards. The Wish list side also shows a quiet total / stores / categories line.
- **Quieter explainers:** "Only you can see these" on Maybe shows for the first 3 visits (`wishlist-hints-seen`) or while getting started; "Surprises stay hidden from you" only shows while getting started.
- **Brand:** `items.brand` (migration 0020). Autofill reads it from JSON-LD `brand`, `product:brand` meta tags, Amazon's byline, a Shopify product's `vendor`, or the Gemini lookup. Editable in the wish form (Add details on a new wish).
- **Edit wish:** grouped into the item, Details, and On your list, with Save and Remove pinned to the bottom of the sheet so they're always in reach on a phone.
- **Ideas and suggestions:** an idea about someone is private to its author. "Share as a suggestion" shows it to everyone in the family except the person it's for, who never gets it from the API.
- **Chat about a person:** "Chat about Mom" on her page is a thread for everyone in the circle except her (one thread per circle, `chat_messages`, migration 0026). She never gets a message, count or badge from it. Messages can be tagged to one of her wishes or a shared suggestion (the chat button on each card), and tapping the tag jumps to it. Unread counts show on the Circles tab. Edit your own message for 15 minutes; remove your own, or anyone's if you're the circle admin. Polls every 20 seconds while open. Messages are kept 6 months. Plan: `docs/plans/hidden-chat.md`.
- **Autofill:** pasting a link (or typing one and leaving the box) calls `/api/preview`. Steps:
  - **Clean the link.** `cleanLink` drops tracking parameters (`utm_*`, `gclid`, `fbclid`, `ref`, Amazon's `ref=`/`th`/`psc`, Walmart's `athbdg`, ...) but keeps variant, size and color ones, and trims Amazon to `/dp/ASIN`. The cleaned link replaces what was pasted.
  - **Amazon.** Amazon blocks most requests from Cloudflare, so: share links (`a.co/d/...`, `amzn.to/...`) are followed to the real `/dp/ASIN` page first; the link's product words are kept as a name guess before trimming; the Gemini lookup is told the ASIN and to search Google for it, plus any share text; and if there's still no photo, it comes from Amazon's image-by-ASIN links. In the app, share text ("Check out X!") beats a name guessed from the link.
  - **Read the page.** Name, price and photo come from JSON-LD, Open Graph tags, or Amazon's markup.
  - **Look up what's missing.** Many big stores (Walmart, Etsy, Best Buy, Kohl's, Nordstrom, Lululemon) block requests from Cloudflare's servers or show a bot check (`BOT_PAGE`). When the page gives no name, photo or price, Fill asks Gemini to look the link up through Google (URL context, then Google Search). The page's own details win, and the lookup only fills gaps. A looked-up name must share a word with a descriptive link, and a photo must actually load as an image.
  - **Fall back to a guess.** If nothing worked, the name is guessed from the URL, and the app says so.
  - **Cache.** Results are cached for a day per cleaned link in Cloudflare's edge cache (no D1).
  - **In the app:** a newer Fill always wins over one still running, and it says "Still looking..." when the lookup is slow.
  - **Logs:** `wrangler tail` shows one `preview <site> ...` line per lookup, with how it was filled.
- **Size and color:** wishes have Size and Color fields (`items.size`, `items.color`, migration 0015). They show under the link for clothing, shoes, and bags & jewelry (picked or guessed from the name), or whenever the link offered choices.
  - **Where the choices come from**, best first: a Shopify store's public `/products/<handle>.js` (every option, plus the variant `?variant=` picks; it also rescues name, price and photo when the page itself is blocked), then JSON-LD (`ProductGroup.hasVariant`, or `size`/`color` on the Product), then the link's query (`?color=navy&size=M`). The Gemini lookup for blocked stores also reports choices.
  - **The form:** a store's list becomes a dropdown with "Other..." to type. Otherwise it's a box with common suggestions. Your profile sizes show as one-tap chips: shirt and pants for clothing, shoe for shoes, ring for jewelry.
  - **On cards:** "Size M · Navy" on your list and on others' lists.
  - **Saving:** the Top pick toggle doesn't send size or color, so it leaves them alone.
- **Live prices:** on someone's list, each wish or idea that's still available and has a link gets a line under its price. Examples: "↓ Now $29.99 at walmart.com" (cheaper than listed), "Now $49 at target.com", "✓ $45 right now at etsy.com", or "Out of stock at kohls.com right now". Details:
  - `POST /api/prices` takes up to 12 `item:`/`idea:` keys you can see.
  - Price and stock status come from the store page (JSON-LD `offers.availability`, `product:availability`, Amazon's markup). Gemini is used only for stores that block us, 4 at a time.
  - Each link is checked at most every 12 hours. Misses are cached for 6 hours, in the edge cache, not D1, and the app remembers answers for the session.
  - Nothing is saved to the item. The owner's own price stays as listed.
  - `wrangler tail` shows `live <site> ...` lines.
- **Clean up a name (✨):** `/api/name` sends the wish's name, link and brand (text only, no tools) to Gemini and gets back a short, clear name. Each tap passes the names already tried so it offers a different one; the app shows Undo. Rate limited per person (`namePerMember` in `src/limits.js`) and counts toward `GEMINI_DAILY_CAP`.
- **Photo search:** `/api/identify` sends a shrunk photo to Gemini (`GEMINI_MODEL` in `wrangler.jsonc`) with Google Search turned on, for up to 4 matches. Each match gets a store link: the brand's own site first, then retailers in `src/stores.js`, then Amazon. Amazon ranks with the retailers only when the page shows it is shipped and sold by Amazon. Every link is opened to confirm it is a real product page (or, if the store blocks bots, that Google Search really returned it). Marketplaces and resellers are never linked. With no confirmed page, the link searches the likeliest store instead. Search grounding is billed per search after 5,000 free a month. If search isn't available (free plan, search quota, or daily limit), it retries without search, so you still get names and store-search links. To keep token cost down, `src/gemini.js` asks for medium image resolution and low thinking (dropped automatically if a model rejects them), and waits out per-minute rate limits up to twice before giving up. Errors say which limit was hit; the raw Gemini error is in `wrangler tail` and the browser console. Photos are not stored.
- **Photos:** pasting a link saves the store's product photo with the item (`image_url`, hotlinked, never copied). Items saved before that, or whose link changed, get their photo looked up once in the background (`POST /api/image`). With no photo, the tile shows a small drawing picked from the item's name (perfume bottle, book, sweater, headphones, gift box, and so on). Columns added in `migrations/0005_item_images.sql`.
- **Someone's list:** a summary (wishes, still available, and top picks or what you're getting; no price range, so nobody gets called out for pricey lists), category chips with counts, price-range chips, a "Still available only" switch, and sort (top picks first, lowest or highest price, newest). Filters reset when you open a different person. Cards show photo, price, category, when it was added, the owner's note in its own box, and a gold Top pick ribbon.
- **Group gifts and "more than one":** plan in `docs/plans/group-gifts.md`, migration 0023.
  - **How many:** the wish form has How many? (1 to 10, or "As many as I like", stored as `items.quantity`, 0 = no limit). Cards show "Wants 3", and others see "1 of 3 still needed".
  - **Several buyers:** `claims` is keyed by `(item_id, season, buyer_id)`, so a wish can have several buyers, each with a `qty`. Buying asks how many (up to what's left).
  - **Group gifts:** "Go in on it together" (single wishes only) starts one. Its rows are `claims.chip_in = 1`, they count as one of the wish together, and `price_cents` is each person's share. Others see "Group gift · Ann and Bob · $70 of $120 so far" with Chip in. A group gift is never shown as taken, and everyone in it shares its occasion.
  - **What the API sends:** `GET list` sends `gift` (`giftOut()` in `src/wishlist.js`) plus `claim`, which is your own mark or a summary once nothing is left, so "still available" is still `!claim`.
  - **Budget:** a share counts as your amount ($0 until entered), and several of one wish count each. The owner never sees any of it.
- **Received wishes:** plan in `docs/plans/received-wishes.md`, migration 0034.
  - **Held:** once an occasion passes, a wish someone marked for it is held (`items.held_season`). It's off everyone's shopping view (`ITEM_VISIBLE`) and in a "Did you get these?" card at the top of My list.
  - **Answers:** **Got it** moves it to **Received** (`received_at`, `received_season`). **Still want it** settles it (`settled_season`) and puts it back without asking again for that occasion. **Got them all** answers every one. The owner never learns who marked what.
  - **Timing:** `settleReceived()` runs hourly and whenever a list is opened. A wish held 30 days is received automatically. "As many as you like" wishes are never held.
  - **Received section:** at the bottom of My list, with a Thanked check and Put back (`item/got`, `item/thanked`, `item/unreceive`, all taking `as` for people you look after). Managers see the card and section on that person's page.
  - **Removing a wish** that has any mark, past or upcoming, now keeps it soft-removed so gift history survives.
- **Gift history:** plan in `docs/plans/gift-history.md`, migration 0035.
  - **Snapshot:** once an occasion passes, `snapshotGifts()` (hourly, and right before a wish or idea with past purchases is deleted) copies every purchase into `gift_history`: title, link, photo, spent (the tracker's rule: paid, else price times how many, and a group gift share counts only what you entered), how many, and group gift. Wishes, ideas and gift cards all count.
  - **Where it shows:** **Budget > History** lists it by year, then occasion, with year totals and search. Someone's page shows "You've given Sam" (the last 5, plus See all).
  - **Who sees it:** `GET history` returns your gifts, plus your household's gifts to people outside it (labeled "from Mike"), the same rule as shared budgets. The person the gift was for never sees it.
- **Share links:** plan in `docs/plans/share-links.md`, migration 0036.
  - **Making one:** at the end of My list, "Share your list with someone outside your circles" (and More > Share on the card of someone you look after) makes a read-only link, `/s/TOKEN` (`members.share_token`, `share/link`). You can copy it, share it, make a new one (the old one stops working) or turn it off.
  - **The page:** `sharePage()` in `src/wishlist.js`, routed in `src/worker.js` under the burst rate limit. It's server-rendered and shows the name, photo, bio, wishes (published, not held or received, not hidden from any circle), gift cards, sizes, loves and favorite brands.
  - **Left out:** purchase info (so it's safe for the owner to open), drafts, notes, nopes, allergies and "already has". It's `noindex` and never cached.
- **Gift cards:** separate from wishes. On My list, tap Add gift cards and pick stores from a grid (search, tap on and off, save), no details needed. They stay on the list every year and are never "taken": anyone can tap one on someone's list, pick the occasion, optionally enter an amount, and it counts toward their budget and the Excel export. The owner never learns who is giving one; other givers see a count ("1 other is giving one"). Removing a brand someone already gave keeps it for them, flagged "Removed". Brands live in `public/giftcards.js` (one list for the app and the API; never change a key). Each gift belongs to an occasion like a purchased mark (Christmas, or their birthday if they added one) and resets after it; the brands themselves stay. Tables `gift_cards` and `gift_card_gifts` (migration 0012).
- **Categories:** the owner can pick one in Add details (`items.category`, migration 0006); otherwise it's guessed from the title (`CAT_RULES` in `public/index.html`). The list must match `CATEGORIES` in `src/wishlist.js`.
- **Missing prices:** a wish with a link but no price gets its price read from the store page once, in the same background lookup as photos (`POST /api/image`, `price_checked_at`). It only fills an empty price, so the owner's own price always wins.
- **Details refresh:** wishes and ideas saved before a newer link field existed get re-read from their link once, in the background after sign-in (`POST /api/refresh`, a few per call, the app keeps calling until done). Everything except the name and notes: photo, brand, size and color fill only when empty, and the price is set from the store and synced from then on (replacing a typed one). Each row records which refresh it had (`details_v`, migration 0021); new and edited rows are stamped current. Bump `DETAILS_V` in `src/wishlist.js` when a new field is filled from links.
- **Price sync:** a price filled in from the link (Fill, a photo match, or the missing-price lookup) is marked `price_auto` (migration 0019), and the form says "Synced with the store." Live price checks (`POST /api/prices`) then update the saved price to what the store charges now. Typing your own price turns syncing off for that wish or idea, and filling from a new link turns it back on. Prices someone paid (claims) are never touched.
- **Maybe (drafts):** My list has a switch at the top: **Wish list** (what your circles see, and where My list opens) and **Maybe** (private, with a lock and a dashed, tinted look). Add to Maybe saves a new wish there, for ideas you aren't sure about yet; saving one jumps to Maybe, and publishing flies the card to Wish list. The Wish list side shows a "N maybes waiting" row when you have any. Only you can see them: the API never returns drafts to anyone else, they don't count toward your wish count, and they can't be marked purchased. Tap Publish (with a confirm) to move one to your wish list, or use Add to wish list when adding to skip Maybe. Publishing is one way: a published wish can't go back to Maybe, only be edited or removed. Top pick and per-family hiding only apply to published wishes. Column `items.draft` (`migrations/0010_just_me.sql`); existing wishes stay published.
- **Profile:** Settings opens with Your profile: name, birthday (month and day, no year), sizes (shirt, pants, shoe, ring), favorite brands (typed or picked, shown as chips, up to 20) and dislikes and allergies (shown as "Avoid"). Family sees it as a "Good to know" card at the top of your list, with a countdown when your birthday is within 45 days. Columns `members.birthday`, `sizes` (JSON), `avoid` (migration 0009), `brands` (JSON, migration 0012).
- **Just for fun (profile):** under Your profile, pick up to 5 gift styles (short chips like "Surprise me", "Stick to my list", "Experiences"; a ? explains the section; Surprise me and Stick to my list swap with each other), any number of favorite colors (swatches) and any number of **colors to skip** ("I hate orange"; shown crossed out), plus one line of "Little things I love" for stocking stuffers. They show on your list's Good to know card. A color can't be both a favorite and a skip: picking it on one row takes it off the other, and the API drops it from skips if both come in. The profile cover still uses your first few favorites. Columns `members.gift_style`, `colors` and `colors_no` (JSON arrays of keys, migrations 0013 and 0030) and `loves`. The keys are listed in both `src/wishlist.js` and `public/index.html` (GIFT_STYLES, FAV_COLORS); never rename one.
- **Profile (loves and nopes):** the Profile tab is your page exactly as your people see it, like a social profile: a cover painted in your favorite colors (wine and gold until you pick some), photo, name, a one-line bio, a birthday pill, and counts (loves, nopes, circles). Below it: **Loves** and **Nopes** as tag chips with an emoji guessed from the words (`TAG_EMOJI`, plain dot when nothing matches), **Good to know** (size tiles, gift style, brands, colors) and an **Allergies and hard nos** callout. Edit profile (or any card's Edit) opens one page of cards with a sticky Save bar. Loves and nopes: a Loves/Nopes switch, a box that takes several at once ("cats, coffee"), tap a chip to move it to the other side, x to remove, and tap-to-add ideas (`TAG_IDEAS`). Up to 30 each, 40 characters; the same thing can't be in both (`members.likes`, `dislikes`, `bio`, migration 0017). The old one-line "Little things I love" shows as loves (split on commas) until the profile is saved once, which clears it. On someone's page, their bio, loves and nopes sit above Good to know, and loves you share are gold ("You both love Cats and Pokémon"). **Nope heads up:** when a gift idea's name or note matches one of the person's nopes (same words in order, singular or plural, accents ignored: "fuzzy sock set" matches "Fuzzy socks", "steak" doesn't match "Tea"), the form shows "Heads up: Sam put Ties in their nopes" and Save becomes Save anyway. It never blocks. If a pasted link filled the name without typing, the first tap shows the heads up and the next one saves. Nopes come with each person in `GET me` (`nopes`), since they're on that person's page anyway.
- **App color:** Settings > Look and feel picks Wine (default), Navy, Plum or Clay, in light and dark. It's per device (`wishlist-accent` in localStorage, applied in `<head>` before paint) and changes the action color, soft tints and header band. The palettes are the `[data-accent]` rules in the CSS.
- **Last names and same-name people:** `members.name` is the first name (what the app shows); `members.last_name` is optional (migration 0030). Two people with the same first name can share a circle when they're in different households, or one is in a household and the other isn't (uncle Freddy with his wife, cousin Freddy on his own). Otherwise the second one needs a last name, and the API says so ("Someone named Freddy is already in Fam. Add a last name to tell them apart."; `SAME_SLOT` and `nameClash()` in `src/wishlist.js`). "Yes, add me" on the join screen always makes someone new: typing a name that's taken never signs you in as them, it asks you to tap your name or add a last name. When two people you can see show the same first name, the app adds a small tag on the Circles tab and their page (`dupeTag()`): their household if it differs, else their last name, else "On their own" for the one not in a household. A "Add your last name" card shows on My list only when someone in your circles has your first name and you have no last name. Before sign-in, the join screen only tags duplicate first names, with a last initial or else the household name. Your own nicknames ("Uncle Freddy", "Cousin Freddy") also work and are only for you.
- **Who I'm buying for:** Budget > People > "Who I'm buying for" switches off a household or one person you've agreed not to exchange gifts with. Only you see it. They drop off the People tab, its totals and "still need a gift for", and the birthday and Christmas push reminders; their purchases and ideas stay. Table `budget_skips` (author, target `m:<memberId>` or `h:<householdId>`, migration 0031); a household switch also covers people who join it later. Route `budget/skip`, and `GET tracker` returns `skips` plus `skipped` per person.
- **Nicknames:** on someone's list, the Edit button sets your nickname for them and your budget for them in one sheet. The nickname lets you call them what you call them ("Grandma" instead of "Jane Doe"). Table `nicknames` (`migrations/0003_nicknames.sql`).

- **Circles tab:** refetches wish counts every time it opens. A "2 new" badge marks people who added wishes since you last opened their list. It's kept on the server (`list_seen`, migration 0027: how many wishes their list had when you last opened it; `seen` in `GET me`, `POST seen`), so it's the same on every device. Each device sends its old local copy (`wishlist-seen`) once so nobody's badges reset. The installed app's home screen icon shows the total (`setAppBadge`, where the phone supports it), and the wish digest notification updates it while the app is closed.
- **Budget:** a countdown under the total ("47 days until Christmas", or the next birthday), and a "Still need a gift for" row of people with nothing yet for that occasion (shown once at least one person has something). Your private budget per person per occasion, what you're getting them, and your open ideas. A switch flips between Christmas (everyone) and Birthdays (soonest first, plus who hasn't added one). Download it as Excel from Settings > App (Christmas or Birthdays). The URL hash is `#budget` (the old `#notes` still works).
- **Budget walkthrough:** the first time someone opens Budget with people to plan for, five spotlight steps explain the total, "+ Budget", the Christmas/Birthdays switch, "Shopping for N of M people · Change" (who you're buying for, right under the switch), and Add a purchase (seen per device, `wishlist-budget-tour`; "How it works" in the hero replays it). A person with no budget shows a tappable "+ Set budget" pill that opens the budget sheet directly; the sheet says in one line what the budget covers and who sees it, and has quick amounts ($25 to $500).
- **List walkthrough:** the first time someone opens another person's list with wishes still open, spotlight steps explain tapping a wish for details, "I'll get this" (marked for everyone else, goes in your Budget, Edit takes it back), splitting a gift ("Go in on it together", or "Chip in" when a group gift is already going; explained on an open wish when no wish offers it), a wish someone else is getting, asking the circle, and "Still available only". Steps whose button isn't on the page are skipped. Seen per device (`wishlist-person-tour`); "How it works" in their hero replays it. Not shown on lists you manage. Budget and this share one spotlight engine (`coachTour`).
- **Shared household budgets:** a household gives together. When you're in a household and the person you're shopping for isn't in it, everyone in your household shares one budget for them and sees what any of you bought for them (who got it, stage, where it's hidden). At Christmas the budget covers their whole household (one "Maria & Nolan" card on Budget > People, one row in the Excel export); birthdays stay per person. Anyone in the household can move a shared purchase along or say where it's hidden; only the buyer can change its price or take it back. Budgets and purchases for people inside your own household, and everything for someone with no household, stay personal. The people a budget is for never see any of it. Table `household_budgets` keyed on (giving household, target `h:<householdId>` or `m:<memberId>`, season); migration 0029 moved existing cross-household budgets in, keeping the higher one when two people had set one for the same person and adding a household's people together at Christmas. The Christmas and birthday push reminders count the household's purchases too.
- **Budget tabs:** Budget has three tabs (remembered per device, `wishlist-budget-tab`). **People** is the budget view above. **Purchases** lists every gift you've bought for anyone's upcoming occasion (Christmas and birthdays months out), grouped by occasion, each with a stage: Ordered, Have it, Wrapped, Given. One tap moves it to the next stage (with Undo); tapping the row edits the stage, where it's hidden ("hall closet"), and the price paid, or takes the purchase back. Filter chips by stage (On the way, To wrap, Wrapped, Given). **Ideas** lists your open ideas by person, with a quick add for people who have none. Stage and hiding place are columns `status` / `stash` on `claims`, `idea_claims` and `gift_card_gifts` (migration 0016), only ever returned to the buyer, set with `POST /api/purchase/progress`, and included in the Excel export.
- **Circles, households, people:** three layers. A *circle* (the `groups` table; the app used to say "family") is who you share lists with: "Family Christmas", "Book club". A *household* is optional: a few people who live or gift together. A circle can hold whole households and single people. In Settings > Household you add people you share a circle with (this starts a household if you don't have one), name it (empty = first names, "Alexis & Sam", same rule in `householdLabel()` in `src/wishlist.js` and `householdAuto()` in the app), and switch it on per circle. On means everyone in the household is in that circle, including people added later; off (or leaving the household) drops people who were only in it through the household, but never someone's last circle. You can't leave a circle your whole household is in. The Circles tab is headed by the circle's name and picture (with Manage for the admin, and Invite), then filter chips (Everyone, Kids, one per household; the row fades at whichever edge has more) and a search box once there are more than 12 people. People are grouped under small household subheadings (tap one for the household page; its pets show next to the name): yours first ("My household"), then the others by name, then "Not in a household" (no subheadings at all when nobody is in a household). People you turned off in Budget > Who I'm buying for go last under "Not on your gift list", faded and without budget or "you're getting", with a Change link to the same sheet. Each card shows the name, "new" and chat badges, wish count and what you're getting, Kid and birthday-soon chips, and the budget bar. A **Catch up** row at the top has a small tile for anyone with new wishes, unread chat, or a birthday in the next 2 weeks (a chat-only tile opens the chat); it hides while a filter or search is on, and when there's nothing. The full invite ticket only shows while it's just you; "Add someone who doesn't use the app" sits at the bottom. Each circle has one **admin** (`groups.created_by`). The admin sees **Manage** on that circle in the Circles tab: photo and name (`family/edit`), **Manage households** (make households from the circle's people, put a new one in that circle, rename them, add or take people out: `household/create`, and `householdId` on `household/add`, `remove`, `rename`, `photo`, `circle`), handing admin to someone else in the circle (`family/admin`), and taking someone out (`family/remove`; not people who are in through their household, and someone taken out of their only circle is signed out). Everyone else can only manage their own household, from Settings > Household. If the admin leaves the circle (or drops out with a household), `adminOf()` passes it to whoever has been in it longest (people in it directly first). Under the hood households are synced into `group_members` (`direct = 0` for "only through the household"), so every "do these two share a circle?" check stays one table (migration 0014). The admin starts as the person who started the circle (circles from before migration 0018 count the first person who joined). Circles and households can have a photo (`family/edit`, `household/photo`, served by `GET photo?g=` / `?h=`); without one they show up to two initials on a rounded square, so they don't look like a person. The API paths still say `family/*`.
- **People you look after:** for kids and anyone who won't use the app (plan: `docs/plans/managed-people.md`). Circles tab > "Add someone who doesn't use the app" makes a person with `members.managed_by` set to you (migration 0022), in the circles you pick and in your household if you have one. Whoever added them and anyone in the same household can manage them (`canManage()` in `src/wishlist.js`). On their page a "You look after" card has Add a wish for them (hidden while their list is empty, where the big "Add the first wish" button does the same thing), Edit profile (name, birthday, photo, sizes, loves, nopes, allergies), Gift cards, Let them sign in, and Remove; each wish gets an Edit button. Writes for them pass `as: memberId` to `item/save`, `item/remove`, `giftcards/save` and `profile` (never a PIN). Their wishes skip Maybe and per-circle hiding. Managers still see purchased marks. Managed people never show on the join screen, can't be signed in as (by id or name) until **Let them sign in** (`managed/release`) clears `managed_by`, and are never made a circle's admin. `managed/remove` takes them out of every circle.
- **Household picture and the "You look after" card:** a household without its own photo is split down the middle between two of its people (you first, then people with a photo), from `memberIds` on each household in `GET me` (`tileAvatar()`). Adding someone who doesn't use the app asks "Add to my household" (off by default, `joinHousehold` on `managed/add`); only then do they join your household. People who don't use the app never count as sharing your budgets. The "You look after" card shows which household they're in, with "Not in our household?" to take them out of yours (they keep their circles), three buttons, and More (hand off, invite, let them sign in, remove).
- **Kids and filters:** whoever looks after someone can mark them a kid ("They're a kid" when adding, "is a kid" on their profile sheet; `members.is_kid`, migration 0033; no ages are stored). Kids get a Kid chip on their Circles card. Circles has a scrollable filter row: Everyone, Kids (when there are any), and one chip per household (yours first, as "My household") when there's more than one. **Sizes** remember when they last changed (`members.sizes_at`; NULL before 0033): sizes three months old show "Sizes updated 5 months ago" on their page, and a kid's "You look after" card nudges to add or update sizes (saving that sheet confirms them, `sizesChecked`). **Already has** (`members.owns`, tags like loves/nopes) shows on their page, is editable on your profile (Sizes card) and theirs, and an idea that matches it gets a heads up, the same way Nopes do.
- **Hand off someone you look after:** "Hand off to someone else" on the "You look after" card picks anyone in their circles who uses the app (`managed/handoff`), say a cousin taking over her baby's list. That person becomes `managed_by`, the managed person moves into their household (or out of the old one if they have none) and stays in every circle they share, and any pending personal invite link stops working. The baby still never needs a login. The circle admin can still help, same as before.
- **Set everyone up, then invite them:** a circle's admin can add whole households of people who aren't on Hints yet (Manage households > Add a household, `household/new`) or add one person to any household (`managed/add` with `householdId`), add wishes for them, then tap **Invite** to send each person a personal link (`/join/CODE?hi=TOKEN`, `managed/invite`). Opening it signs them in as themselves and hands the list over (`invite/claim`), no shared PIN. Only a hash of the token is kept (migration 0028). The link is reusable: after it hands the list over, opening it again signs that person in on a new phone (asking for their PIN if they set one) until a new link replaces it or it's turned off. Everyone can also make their own sign-in link in Settings (`me/link`). The circle link works too: people someone set up (not kids) show on its name list as "Ready for you", and tapping your name takes the list over (`join` with `memberId`), then the welcome tour offers a PIN. When anyone is waiting, that screen leads with the names so nobody makes a second list, and the circle invite message says to tap your name. Admins can manage anyone in their circles who hasn't joined yet, so handing admin over hands that over too.
- **Household pages and pets:** every household has its own page (`#household/<id>`, `renderHousehold()`): its picture and name, its people, and its pets. You get there from the household card on someone's page ("Household: Alexis & Mike · Lives with 🐕 Biscuit"), your Profile, or Settings > Household. People in the household (and a circle's admin, the same rule as `manageableHousehold()`) can rename it, change its photo and edit its pets from there. **Pets** aren't people: no list, login, birthday or chat, just a name, a kind (dog, cat, bird, fish, bunny, reptile, horse, other), one line of notes ("size L harness") and an optional photo, so gift-givers know about them. A pet belongs to a household, or to someone who isn't in one (table `pets`, migration 0037, never both). Joining a household brings your pets into it; when the last person leaves a household, they take its pets. Anyone who shares a circle with the household (or the person) sees them; `GET me` returns `pets` keyed `h:<householdId>` / `m:<memberId>`. Someone without a household shows a Pets card on their page and Profile; whoever looks after them can edit it too. Routes `pet/save` (new or `id`; `householdId` or `as`; `photo` data URL, `""` removes) and `pet/delete`; photos are served by `GET photo?p=`. Plan: `docs/plans/household-page.md`.

Each wish has a "Who can see this" switch per family; a wish hidden from a family is never shown through that family (`item_hidden`, migration 0004), though anyone who shares another family with you where it isn't hidden still sees it. The Circles tab shows a section per family (left out while a filter matches no one in it), with the Catch up row, filter chips and search shared above them. Joining is blocked if that family already has someone with your name. Opening an invite link while signed in opens Settings with the code filled in.

  - **Asking:** never on page load, always from a tap. Besides Settings: a "Want a heads up when your people add wishes?" card on My list (once you share a circle with someone, never alongside the install card or during the tour; Not now snoozes 7 days, then 30, then stops, per device in `wishlist-push-nudge`), and a "Hear about new wishes" card in the welcome tour. Both only show where it can be turned on right there (not in an iPhone Safari tab).
  - **Belongs to the sign-in:** each subscription stores the device token that turned it on (`push_subs.device_token`). Nothing is sent to a subscription whose device is signed out, bumped by the device cap, or removed, and the hourly run deletes those. Signing out also unsubscribes the browser, so the next person on that phone starts with notifications off and never gets the last person's (chat text included). The app re-registers its subscription on every start.
  - **Quiet hours:** nothing between 9 pm and 8 am New York. Group gift and chat notifications that come up overnight wait in `push_later` (newest per tag) and go out with the 8 am run; the wish digest just waits for the morning.
  - **Sending:** `src/push.js` signs (VAPID, ES256) and encrypts (RFC 8291 aes128gcm) with WebCrypto, no libraries. The key pair is made on first use and kept in D1 (`app_keys`), so there's no secret to set. Subscriptions live in `push_subs`, only for real push services, and ones that come back 404/410 are deleted.
  - **When:** an hourly Cron Trigger (`triggers` in `wrangler.jsonc`, `scheduled()` in `src/worker.js`, `runSchedule()` in `src/wishlist.js`) sends "Sam added 2 wishes" for wishes published since the last run, to people who can see them, skipping people you look after. From the 9am New York run it also sends birthday reminders (14 and 2 days out, never to the birthday person), on Dec 1 and Dec 18 "Christmas is in N days. Still need a gift for ..." only if you do, and from Nov 15 "Your list hasn't changed since last year" to owners whose published list wasn't touched this year (once a year, not after Looks good). `push_sent` stops anything going out twice, so a run that stops early is picked up by the next one. The digest's cursor only moves once everyone has been handled.
  - **Free plan:** one run sends at most 35 notifications (each is an outgoing request; the free plan allows 50 a run), and the signed VAPID token is reused per push service for an hour to save CPU. Leftovers go out the next hour. Starting a group gift notifies everyone who can see that wish except the person it's for. A chat message notifies everyone in that circle except the person it's about and the sender ("New message about Sam", or the sender and text if they turned on Show message text), once per unread stretch (nothing more until they open the chat, unless their unread messages are over a week old). It links to `#person/ID/chat/CIRCLE`, which opens that chat.
  - **Opening:** `public/sw.js` shows the notification (status bar icon `icons/badge.png`, a white H, since Android draws it as a silhouette), sets the home screen badge when the payload has a count, and tapping it opens the right screen.
  - **Testing locally:** put `PUSH_DEV_ENDPOINT=http://localhost:9911/` (lets a fake push service subscribe) and `PUSH_DEV_REMIND=1` (reminders on every run), and optionally `PUSH_DEV_HOUR=9` (pretend New York hour, for quiet hours) and `PUSH_DEV_TODAY=20261115` (pretend date for reminders) in `.dev.vars`, run `npx wrangler dev --test-scheduled`, and trigger a run with `curl "localhost:8787/__scheduled?cron=0+*+*+*+*"`. Never set these in production.

## Abuse limits

All the numbers live in `src/limits.js` (`LIMITS`), counted in the `rate_limits` table (migration 0024) plus a per-IP burst cap from the `BURST` rate limit binding in `wrangler.jsonc` (240 API calls a minute per IP).
- **Sign-up:** per IP, 4 new circles and 8 new people a day; whole app, 100 new circles and 300 new people a day. Invite code lookups (including `/join/CODE` previews) 40 an hour per IP, sign-in attempts 30 an hour.
- **PINs:** 8 tries per 15 minutes and 20 a day per person, 30 an hour per IP. A 4-digit PIN would take over a year to guess.
- **Caps:** 300 wishes and 500 gift ideas per person, 20 circles per person, 100 people per circle, 40 people you look after (40 new a day, 80 invite links a day), 15 signed-in devices per person (the least recently used is signed out). Request bodies over 400 KB (6 MB for photo search) are refused.
- **Cost:** per person, link fills 80 an hour and 300 a day, photo searches 15 an hour and 40 a day, plus hourly caps on live prices, details refresh and photo lookups (those quietly return nothing when over). Whole app, Gemini calls are capped at `GEMINI_DAILY_CAP` a day (1,500 by default).
- **Outbound fetches** (store pages, photos) only go to normal public sites: no IP addresses, internal names or odd ports, every redirect checked, at most 1.5 MB read.
- **Headers:** every response gets nosniff, no framing, HSTS, a strict referrer policy and a locked-down permissions policy.
- Over a limit, the API answers 429 with a friendly message the app shows as is.
